5kBLOCKED_BY_PRODUCT_CAPABILITY — new findings from this turn
Notifications have no delivery path. Tables, a category enum, push-token storage, a transactional outbox and an exhaustive collapse-rule table all exist. Nothing drains the outbox into a tray, and the app has no notifications route. 5e is drawn from the rule table and is not a picture of working software.
Search cannot find a topic or a classroom. Results are people, content, groups and communities. The topic graph that Learn, Topic and Practice are built on is unreachable from search, and so is every classroom.
Messages carry no structured references. A message is a body plus a deletion timestamp. There is no shared-topic, shared-post, classroom or provenance attachment type, so none is drawn — a student can paste a title, and that is all.
No message attachments at all. File upload exists for posts, not for conversations.
No classroom live status, no attendance, no teacher analytics, no grading. A classroom is identity, membership, roles and a lecture list. Nothing measures who attended or how anyone performed.
No practice from a classroom or a lecture. Practice is reachable from a topic. Nothing links a lecture to the topics it covers, so “practise this lecture” cannot be offered.
No drafts. Compose holds text in memory only.
No follower counts. Following exists as a relationship; no count is exposed, so none is shown.
Still blocked from Turn 4: mastery, confidence, readiness, adaptive sequencing, prerequisites, recommendations, spaced repetition, resumable partial attempts.
Cross-screen audit — Learn → Classroom → Message → Search → Topic → Practice

Does it read as one product? Yes, and the load-bearing reason is the metadata line. Every screen states its facts the same way, at the same size, in the same colour, so a student never has to learn a second way to read a fact. Second is the header: back arrow, crumb, editorial title, 2px ink rule, on classroom, topic, profile and search alike.

One information architecture? Mostly. Knowledge appears in the feed, in a topic, in search and on a profile, and it looks the same in all four — type as metadata, serif body, provenance rule. The gap is that search cannot reach a topic or a classroom, so the architecture the rest of the product exposes is not navigable from the one screen whose job is navigation. That is a product gap, not a design one, and it is the first thing I would fix.

One academic worldview? The tell is what the product refuses to say. It will not claim you know a topic, will not celebrate a correct answer, will not notify you that you were wrong, will not tell someone they were removed from a group, and will not label your post for you. Those five refusals are visible on five different screens and they are recognisably the same product talking.

Where the seams still show. Three. Follow reuses the group join and leave strings, so a profile says “Join” about a person — an i18n bug worth a real key. The Groups and Classrooms distinction is invisible until you are inside one; search shows both under one heading and they behave differently. And Home and Learn both carry a resume band, which is correct on each screen alone but means a student can meet the same action twice in two taps.

Practice remains the only mode switch. Nothing else in the expansion takes the tab bar away or inverts a header. That is what keeps it meaning something.

Not built, and waiting on your call: post detail with the correction thread, lecture and materials, groups as distinct from classrooms, settings and notification preferences, and the instructor-side classroom.

3cRTL decision log, §46 scorecard, and what is blocked
Typography, resolved per script

Newsreader has no Arabic. Rather than force parity, the display role is kept and the voice changes by script: Latin display is Newsreader 400–500; Arabic display is IBM Plex Sans Arabic 600 at ~1.5× line-height. Body and metadata are IBM Plex Sans / IBM Plex Sans Arabic — metric siblings, so a Latin drug name inside an Arabic sentence keeps the baseline and the colour.

Ten RTL problems, and what each one resolved to
Provenance direction
The 2px rule moves to border-right; the label leads, the citation follows — reading order preserved, not mirrored geometry.
Topic spine
Edges are laid out as label → rule → target, so in RTL the label sits right and the rule grows left. The connector never crosses the text column.
Source syntax
English titles stay LTR inside an isolate (Nelson 21e, p.2521), so the comma and full stop do not jump to the wrong end.
Numerals
Interface counts Arabic-Indic (٣ من ٧, ٥ من ١٢). Clinical and lab values Latin with Latin units (18 g/L, pH 7.1) — that is how they appear in the textbooks and on the ward.
Evidence fractions
“5/12” does not mirror safely, so Arabic uses the word form ٥ من ١٢ instead of a slash. Better than an isolate, and it reads aloud.
Latin abbreviations
